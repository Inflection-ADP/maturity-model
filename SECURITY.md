# Security Policy

## Supported versions

Only the latest version of the `main` branch receives security fixes. If you are running an older fork or a self-hosted deployment, please keep it up to date.

## Reporting a vulnerability

If you find a security vulnerability in this project, please do not open a public GitHub issue. That would expose the vulnerability before it can be fixed.

Instead, email [saisravan@gmail.com](mailto:saisravan@gmail.com) directly with:

- A description of the vulnerability
- Steps to reproduce it
- What you believe the impact is
- Whether you have a proposed fix

You will receive a response within 48 hours confirming the report was received. If the vulnerability is confirmed, a fix will be prioritized and you will be credited in the release notes unless you prefer to stay anonymous.

## Scope

This policy covers the code in this repository. It does not cover the live deployment at [inflection.saisravancherukuri.com](https://inflection.saisravancherukuri.com) beyond what is controlled by this codebase.

## What counts as a vulnerability

- Authentication or authorization flaws
- SQL injection or other injection attacks
- Exposure of private assessment data
- Dependencies with known, exploitable CVEs

If you are unsure whether something qualifies, send the email anyway.
